## 2. 通用设置（三张表都一样）

- **入口**：https://data.csmar.com → 校内网络或学校 VPN → 右上角显示学校名称即登录成功。
- **最稳的找表方式**：不要一层层点菜单，直接用数据中心顶部的**搜索框**搜中文关键词（`审计意见` / `会计差错更正` / `违规处理`），平台会把命中的子库直接列出来——不同学校的菜单层级不完全一样，搜索框是通用入口。
- **时间区间**：见 §4 的窗口表，**不要只填 2021–2023**（事件发生在 t+1，会被截断）。
- **筛选**：全部 A 股即可，**不要在下载端按行业筛**（这几张表行数小，本地按样本框过滤更不容易漏）。
- **导出**：Excel `.xlsx`；同时下载每张表的《数据说明》（文件名形如 `XXX[DES][xlsx].txt`），后面写论文的数据来源要引用它。
- **不要手工编辑 Excel**：证券代码会被 Excel 吃掉前导零，我们的脚本读入时统一 `dtype=str` + `zfill(6)`，手工另存反而会破坏格式。

## 3. 逐表指引

### 表 A：财务报告审计意见（**必下**，分支 3 的全部数据）

- **路径**：数据中心 → 搜「审计意见」→ **财务报告审计意见表**（英文版叫 Audit Opinion / Financial Report Audit Opinions）。
- **时间区间**：会计期间 **2020-12-31 至 2023-12-31**（一年一条，只取年报口径）。
- **目标字段**（字段名各校版本略有差异，按"要拿到这 6 条信息"去勾）：

  | 目标信息 | 常见字段名 | 用途 |
  | --- | --- | --- |
  | 证券代码 | 证券代码 / Stkcd / Symbol | 主键 |
  | 会计期间 | 会计期间 / 报告期 / Accper | 对齐 fiscal_year |
  | **审计意见类型** | 审计意见类型 / 审计意见 / AuditTyp | **核心结果变量** |
  | 境内审计师 | 境内审计师 / 会计师事务所 | 控制变量（Big4、换所） |
  | 审计费用 | 审计费用 / 境内审计费用 | 控制变量 |
  | 审计报告日期 | 审计报告日期 / 报告公告日 | 时间对齐校验 |

  若表里还有「报表类型 / Typrep」，只保留**合并报表**口径。
- **命名**：`data/raw/csmar_events/AUD_OPINION_2020_2024.xlsx`
- **预期规模**：约 4,800–5,500 行/年；全部 A 股三年合计约 1.4 万行。

### 表 B：会计差错更正 / 财务重述（优先）

- **路径**：搜「会计差错更正」→ **中国上市公司会计差错更正研究数据库**（含"财务重述公告表""会计差错更正前后对比表"等多张子表）。
  只下**公告级**那张（一般叫 财务重述 / 会计差错更正公告表），不需要下前后对比明细。
- **时间区间**：公告日期 **2021-01-01 至 2025-12-31**（要覆盖 t+1 与 t+2）。
- **目标字段**：证券代码、公告日期、更正/重述类型、**涉及的会计年度（或"更正年度""所属年度"）**、是否涉及以前年度、更正原因或公告标题。
- **命名**：`data/raw/csmar_events/RESTATEMENT_2021_2025.xlsx`
- **预期规模**：约 1,000–2,000 条/年。

> 若学校没订这个库，**跳过**，不要用巨潮公告标题正则硬凑（假阳性极高：准则变更、同一控制下合并追溯调整都会被误判为重述）。

### 表 C：违规处理 / 监管处罚（优先）

- **路径**：搜「违规处理」→ **中国上市公司违规处理研究数据库**。
- **时间区间**：公告日期 **2021-01-01 至 2025-12-31**（若表里同时有"处理日期"，两个都留着）。
- **目标字段**：证券代码、公告日期、处理/处罚日期、**违规类型**（CSMAR 编码 P2501–P2515，如虚构利润/虚列资产/推迟披露/重大遗漏/违规担保）、**违规主体**（公司 / 高管 / 子公司）、处理机构、处罚方式。
- **命名**：`data/raw/csmar_events/VIOLATION_2021_2025.xlsx`
- **预期规模**：约 1,000–1,500 条/年（记录数 ≠ 公司数，一条违规可能多主体多条记录）。

### 表 D（可选）：特别处理（ST / 退市风险警示）

- **路径**：搜「特别处理」或「ST」→ 上市公司特别处理表。
- **用途**：控制"已被 ST"的公司（这类公司本来就高发事件），也用于检查样本框的幸存者偏差。
- **时间区间**：2020-01-01 至 2025-12-31。
- **命名**：`data/raw/csmar_events/ST_STATUS_2020_2025.xlsx`

## 4. 时间窗口（最容易出错的一步）

事件发生在**报告年度之后**，所以两张时间表要分开设：

| 文件 | 表内日期字段 | 要填的区间 | 理由 |
| --- | --- | --- | --- |
| 表 A 审计意见 | 会计期间 | 2020-12-31 ~ 2023-12-31 | 意见针对的是 t 年报表，天然对齐 |
| 表 B 重述 | 公告日期 | 2021-01-01 ~ **2025-12-31** | 2023 年报的重述可能到 2025 年才公告 |
| 表 C 违规 | 公告日期 | 2021-01-01 ~ **2025-12-31** | 处罚滞后 1–3 年，不拉到 2025 会假阴性 |
| 表 D ST | 变更日期 | 2020-01-01 ~ 2025-12-31 | 控制变量 |

**为什么必须拉到 2025**：我们的样本是 2021–2023 年报。若只下到 2023 年底，2023 年观测的事件几乎必然缺失，回归系数会被系统性压低——这是"看起来没结果"的常见原因之一。

## 5. 下载后自检（5 分钟）

```powershell
# 把下载好的文件放进 data/raw/csmar_events/ 后运行
& ".venv\Scripts\python.exe" "scripts/run_00c_inspect_csmar_export.py" "data/raw/csmar_events"
```

脚本会打印每张表的 sheet、列名、行数、证券代码样例与长度，用来确认：

1. **代码列没丢前导零**：长度应出现 6（如 `000820`）。若显示 `820`，不要紧，我们读入时补零，但要在报告里说明。
2. **行数量级对得上**（见 §3 各表的预期规模）；差一个量级说明筛选条件错了。
3. **审计意见类型列可读**（是"标准无保留意见"这类文字，或 1/2/3/4/5 编码 + 说明文档）。
4. **抽 3 家公司人工核对**：建议 `000820`（我们现在的 top-1）、`600519`（茅台，应为标准意见）、`000002`（万科），到交易所或巨潮核对当年是否真的收到该意见/函/处罚。

## 6. 常见坑（按危险度）

1. **右删失**：只下到 2023 年 → 2023 观测事件缺失。见 §4。
2. **口径混用**：审计意见的"带强调事项段无保留"算不算非标？我们会做两个口径——**窄口径**（保留 / 无法表示 / 否定）为主，**宽口径**（含强调事项段）为稳健性，两者都要能在论文里说清。
3. **重复公告**：同一次重述可能多次公告，同一条违规可能多主体多条 → 分析前按 (证券代码, 涉及年度) 或 (证券代码, 违规类型, 公告年度) 折叠成 firm-year 0/1。
4. **主体口径**：违规表要把"高管个人""子公司"的记录筛掉，只留公司主体，否则事件率虚高。
5. **"公告日期" vs "处理日期" vs "违规年度"**：主口径用公告/处理日期落在 t+1，稳健性换成 t+1 或 t+2 的窗口，看结论是否翻转。
6. **ST 公司被样本框剔除**：我们的样本框 3,694 家已剔除部分退市/ST；退市公司恰恰是事件高发群体，论文里要如实写"存在幸存者偏差，会低估事件率"。
7. **中英文字段**：CSMAR 可导出中文版或英文版，字段名不同。下载时**保持一种语言不要混**，并把 `[DES]` 说明文件一起留下。

## 7. 按订阅权限怎么选（决策树）

```
登录 CSMAR，搜「审计意见」
├─ 能下载 ────────────────────► 走分支 3（非标审计意见），0.5–1 天出结果
│   ├─ 还能下「会计差错更正」 ──► 追加分支 4（财务重述）
│   ├─ 还能下「违规处理」 ─────► 追加分支 5（违规处罚）
│   └─ 还能下「特别处理」 ─────► 加控制变量（推荐）
└─ 不能下载（未订阅）
    ├─ 学校有 CNRDS ──────────► 用 CNRDS 监管问询库（分支 2）
    ├─ 都没有 ────────────────► 交易所官网自建爬虫（分支 2，4–6 人日）
    └─ 时间不够 ──────────────► 保留现行阴性结论 + 已完成的八分量探针证据
                                 （论文写成"负面结果 + 已排除度量解释"，同样可交卷）
```

**判断能不能下**的关键动作：在库页面上每个表都有「已订阅 / 未订阅」标识；未订阅时能看到字段但下载按钮会提示无权限。**开工第一天就把这一步做完**，别等到写代码时才发现下不了。

## 8. 问询函不在 CSMAR（另一条路）

CSMAR 没有结构化的问询函子库。可选来源：

| 来源 | 覆盖 | 成本 | 备注 |
| --- | --- | --- | --- |
| 上交所监管问询页 | 2014– | 免费、需爬 | http://www.sse.com.cn/disclosure/credibility/supervision/inquiries/ |
| 深交所问询函件页 | 2014– | 免费、需爬 | http://www.szse.cn/disclosure/supervision/inquire/index.html |
| 北交所 | 2021– | 免费、需爬 | https://www.bse.cn/disclosure/enquiry_letter.html |
| 巨潮公告检索 | 全量 | 免费、需解析 | https://www.cninfo.com.cn/new/commonUrl?url=disclosure/list/notice |
| CNRDS「监管问询数据库」 | 2014– | 需订阅 | 字段最干净，学校若有直接用 |
| textdata.cn | 2014-12~2023-12 | 付费 | 14,730 条，含函件正文 |

**定义要点**：结果变量 = 公司因 **t 年年报** 在 t+1 年是否收到年报类问询函；必须剔除重组/定增/半年报类问询函，并剔除 t 年已收函的观测（反向因果）。2023 年报的函在 2024 年发出，样本期要相应前移。

## 9. 数据到位后我会做什么

1. 新增 `src/data_ingestion/event_parser.py`：列名别名、代码补零、把公告级记录折叠成 firm-year 0/1（含两套审计意见口径、两套时间窗口）。
2. 新增 `scripts/run_03b_build_event_table.py` → `data/processed/event_table.csv`（键：`symbol` + `fiscal_year`），并打印事件率与覆盖率。
3. 新增 `scripts/run_07b_event_models.py`：logit / rare-events logit（行业×年固定效应、公司聚类稳健标准误），输出 **ΔAUC（DeLong）/ PR-AUC / lift**，把现有无监督分数作为附加列对照；外加四件套稳健性（t+2 安慰剂、剔除 t 年已收函、只留会计类事件、控制上年审计意见/违规/ST/Big4）。
4. 结果无论正负都写进 §5 与 §5.6 的新增小节，并在 `outputs/reports/` 留一份对照报告。
